# Publish to your GitHub account

The delivered files have not been pushed to GitHub. Use these steps after local review and Windows validation. GitHub account authentication is a separate step; never paste tokens into source files or commit messages.

## Prepare locally

Extract the archive, open a terminal in `multi-site-it-operations-lab`, and confirm that the README and `.github` directory are directly inside it.

```bash
git init
git branch -M main
git status --short
git add .
git diff --cached --stat
git diff --cached
```

Inspect the full staged diff. `.gitignore` does not remove a secret already committed, and it cannot protect live files you deliberately force-add. If Git requests author information, set your own name/email locally; no author identity has been invented for you.

```bash
git commit -m "Add multi-site IT operations lab"
```

## Connect the empty remote

Create a repository named `multi-site-it-operations-lab` in your GitHub account. Start without an autogenerated README, license or ignore file, because these are already included. Choose the visibility you want.

Replace `YOUR_USERNAME` below with your actual account:

```bash
git remote add origin https://github.com/YOUR_USERNAME/multi-site-it-operations-lab.git
git push -u origin main
```

Use GitHub's supported authentication flow or a configured credential manager. Do not put access tokens in the remote URL.

## Verify the publication

1. Confirm the README and examples are visible.
2. Open the Actions tab and inspect both Windows and Linux jobs.
3. Download test result artifacts if a job fails; fix failures before tagging a release.
4. Clone into a separate folder and follow the quickstart from scratch.
5. Update `docs/verification.md` with actual evidence, commit and push that update.

Suggested repository description:

> PowerShell lab for multi-site Windows IT support: diagnostics, workstation provisioning, asset validation and support runbooks.

Suggested topics: `powershell`, `windows`, `it-support`, `system-administration`, `homelab`, `portfolio`.

## Tag after verification

Once the release gate in `test-plan.md` is satisfied:

```bash
git tag -a v0.1.0 -m "Initial verified local operations lab"
git push origin v0.1.0
```

Do not add success badges or claim production use without evidence. Describe cloud integrations as planned until implemented and tested.
