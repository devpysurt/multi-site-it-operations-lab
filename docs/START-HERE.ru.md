# С чего начать

Готова первая версия учебного проекта для портфолио: диагностика Windows, подготовка рабочего места, реестр оборудования, инструкции, тесты и CI.

## 1. Открой демо

Открой `examples/workstation-report.demo.html` в браузере. Это статический пример с вымышленными данными: на диске D: мало места, а остановленная служба обновления показана без автоматического вывода о неисправности.

## 2. Запусти команды

Нужен PowerShell 7.4 или новее. Встроенный Windows PowerShell 5.1 не подходит. Открой терминал в папке проекта:

```powershell
$PSVersionTable.PSVersion
./scripts/Get-WorkstationReport.ps1 -Demo
./scripts/Test-AssetInventory.ps1
./scripts/Initialize-Workstation.ps1 -InstallPackages -WhatIf
```

Первая команда проекта создаёт новый HTML/JSON-отчёт и выводит его пути. Последняя показывает план без изменения компьютера. Не копируй приглашение терминала вместе с командами.

## 3. Проверь на Windows

```powershell
Install-Module Pester -RequiredVersion 5.7.1 -Scope CurrentUser
./scripts/Test-Syntax.ps1
./scripts/Invoke-Tests.ps1 -IncludeWindows
./scripts/Get-WorkstationReport.ps1
```

PowerShell здесь не был доступен, поэтому результаты его тестов не выдуманы: точный статус находится в `docs/verification.md`. Запуск на Windows — обязательный следующий шаг перед утверждением, что проект проверен в этой среде.

## 4. Проверь подготовку рабочего места

Без установки программ:

```powershell
./scripts/Initialize-Workstation.ps1
./scripts/Initialize-Workstation.ps1
```

При втором запуске уже созданные каталоги пропускаются. Журналы находятся в `logs/`.

Установку программ проверяй в тестовой Windows VM со снимком состояния. Сначала просмотри `config/workstation.example.json`. Затем, если согласен с условиями выбранных пакетов:

```powershell
./scripts/Initialize-Workstation.ps1 -InstallPackages -AcceptPackageAgreements
```

Скрипт не откатывает изменения установщиков. При ошибке изучи журнал; для полного возврата тестовой машины используй её снимок.

## 5. Подготовь демонстрацию работодателю

1. Покажи реестр трёх площадок и правила его проверки.
2. Сгенерируй демоотчёт, объясни предупреждение о диске.
3. Покажи `-WhatIf`, затем создание каталогов и повторный запуск.
4. Открой JSONL-журнал и одну инструкцию для сотрудника.
5. Покажи настоящий результат Pester после запуска у себя.
6. Объясни, как планируешь подключить Entra ID и Intune; они ещё не реализованы.

## 6. Загрузим на GitHub

Архив содержит корневую папку проекта. Для публикации нужен именно её **внутренний набор файлов**, включая `.github`, `.gitignore` и `.gitattributes`.

Пошаговая инструкция находится в `docs/github-release.md`. До загрузки проверь, что не добавляешь реальные отчёты, логи, конфигурации и данные сотрудников. После подключения твоего GitHub можно создать репозиторий и выполнить публикацию отдельным шагом.
